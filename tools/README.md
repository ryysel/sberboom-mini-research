# Воспроизведение офлайн-анализа

Нужен Python 3.10+ и собственная законно полученная копия исследуемого BIN. Скрипты не содержат кода общения с колонкой.

1. Создайте виртуальное окружение и установите `python -m pip install -r tools/requirements.txt`.
2. Создайте `work/` в корне и положите вход как `work/boom_original.bin`.
3. Сверьте SHA-256 с evidence/input-hashes.json. Адреса в отчётах относятся только к этому конкретному файлу.
4. Выполните последовательно:

```text
python tools/scan-dump.py
python tools/unpack.py
python tools/inspect.py
python tools/verify-verity.py
python tools/inspect-boot.py
python tools/reverse.py
```

`unpack.py` извлекает boot/system из UBI, компоненты FIT, обычные файлы CPIO и SquashFS. Ссылки/спецустройства не создаёт. Разреженные cache/data не восстанавливаются. Результаты и исходники прошивки остаются в игнорируемом `work/`.

`verify-verity.py` привязан к verity-offset этой сборки. Он проверяет данные и дерево, а не подпись производителя или совместимость с устройством.

`reverse.py` — экспериментальный помощник, **не декомпилятор и не полный анализатор ссылок**. Учитывает ARM literal loads, ограниченные MOVW/MOVT и PC-relative ADD; эвристики могут давать ложные ссылки и подписи, не моделируют весь control flow и не поддерживают Thumb полностью. `.ARM.exidx` используется как ориентир границ функций, а не гарантия полного покрытия. Выводы требуют ручной проверки.

## Безопасность входа

Не запускайте извлечённые ELF и скрипты производителя. Парсеры не являются hardened forensic sandbox; для недоверенных дампов используйте изолированную VM без привилегий и важных файлов. Часть путей/смещений намеренно фиксирована для воспроизводимости именно этого исследования.

## Что не делает пакет

Не генерирует JWT/ответы Rabbit Hole, не общается с 20000/USB/UART, не загружает payload, не пишет flash или efuse. Доступ к shell/root не предоставляется.
