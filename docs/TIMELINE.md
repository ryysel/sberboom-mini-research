## 30.10 — маршрут SberCast star-command

- Статически прослежен внешний вход вложенного `StarCommand`: decoder → `onStarMessage` → PIN/backend validator → `processMessage`.
- Исправлена предыдущая ошибка: `0x37b01c` — protobuf-аксессор oneof, а не таблица «case → handler». Реальная диспетчеризация — виртуальный слот 0x28 `AgentService` (0x1718fc).
- Найдены ровно семь реализаций `staros::Agent`; исполнение разрешается только их наборами `supportedCommands()`. Других наследников в ELF нет.
- ADB — отдельный тип `StarMessage` (case 115 по смещению 0x18) с проверкой пароля PBKDF2-HMAC-SHA256, 1000 итераций, 32 байта. По star-command маршруту он недостижим; это не `configHash` и не RS256 Rabbit Hole.
- `MutableConfigService` принимает только case 100 (group mapping/refresh), не произвольный JSON в `CONFIG_OVERRIDE`.
- Собственный layout-скрипт расширен до 62 проверок. Неподключённые вопросы: внешние gates, преобразование `StarCommand → StarMessage`, текущая прошивка.
- Уточнён `result4`: это пустое поле токена; на уровне сообщения он не отказ и идёт в тот же helper, что и успешный result0. Карта `server+0x110` — реестр активных WS-сессий, запись создаётся при `wsOnOpen` без токена; новая сессия имеет auth type `+0xd0 = 3`, а `onStarMessage` штампует 1/0 **до** проверки результата. Принимает ли это gate 0x182d84 — не установлено.
- Колонка, сеть и сервисы не затрагивались; новых подключений к 20000 не было.
